Method and limits

How Trace works, and what each result can and cannot tell you.

Trace reports what authoritative sources say about a file. It does not score the file, and the absence of a signal is never a clean bill of health. This page explains what each check reads, where it fails, and how to get a clearer reading.

What Trace checks

There are two authoritative sources, and one that is read and reported but never trusted as proof.

  1. The SynthID check. Google's official verification API reads the invisible watermark that some generators embed. This is a live vendor verdict.
  2. C2PA content credentials. A signed manifest embedded in the file, read and its signature validated with the official C2PA library.
  3. Metadata. EXIF, XMP and IPTC blocks are parsed and their generator markers reported. Metadata is trivially strippable and forgeable, so it is never treated as proof.

That is the whole list. There is no statistical probe, no spectral or frequency analysis, no error level analysis, no noise estimate, and no badge scan. Those approaches guess, and a guess dressed as a number is worse than no answer. Every result Trace shows comes from one of the three sources above, or states that a check did not run.

Absence of provenance is the normal case, not a suspicious one. Most media in circulation was never signed and never watermarked, and most re-encodes strip whatever was there.

The SynthID check

SynthID is Google's watermark for AI generated images, audio and video. Google runs an official verification service at synthid.googleapis.com/upload/v1:verifyContent. Trace sends the raw file bytes to that service and reports the response exactly as returned.

The service accepts an image up to 8 MB, and audio or video up to 100 MB. It returns a decision: watermarked, not watermarked, an abstention, or unspecified. When the media is watermarked it may also return the producer, and for images a confidence band. It reports how much of the content carries the watermark, as a prevalence band.

Confidence is an image-only field. A video verdict carries no confidence, so Trace does not invent one.

The service needs an API key. The key comes from enabling the SynthID API for a Google Cloud project at the SynthID API page, then creating an API key. The check runs directly from your browser to Google. With no key, the check does not run at all, and Trace reports it as not_configured, which is not the same as a clean result.

If the key's project does not have the API enabled, Google returns API_KEY_SERVICE_BLOCKED. That is an account and project setting, not a limit of the API itself, and the fix is to enable the API for the right project.

An abstention is not a verdict

When the service abstains it could not reach a decision. Each reason says why:

Abstention reasons and what each one means
ReasonMeaning
EMPTY_BYTESThe payload was empty, so there was nothing to read.
LOW_RESOLUTIONThe content was too small to carry or reveal a reliable watermark.
FILTEREDProcessing or filtering removed the signal the service looks for.
LOW_FPSToo few frames were available to judge a video.
LOW_QUALITYCompression or quality loss obscured the watermark.
POSSIBLE_TAMPERINGThe content showed signs of modification that prevent a confident reading.

An abstention is the absence of a verdict. It never means the file is clean.

Prevalence

For watermarked media the service reports the share of the content that carries the watermark, as a band: none, low (under 25%), medium (25 to 50%), or high (over 50%). For a video this is reported per frame and for audio per sample range. A low prevalence often means only part of the file was AI generated, so trimming to the relevant segment gives a clearer reading.

C2PA content credentials

C2PA is a standard for embedding a signed manifest inside a media file. The manifest can name the tool that produced the file, the signer, and the assertions that describe how the content was made. Trace reads the manifest with the official C2PA library and validates its signature, so a manifest it reports as found is one whose signature checked out.

Trace reports the claim generator, the signer's issuer and common name, the signing time and algorithm, and the assertion labels. It reads the provenance declaration from the c2pa.actions and c2pa.actions.v2 assertions.

The digitalSourceType distinction

This field is the part of C2PA most often misread. Four of its values look alike and mean different things:

The digitalSourceType values and what each contributes
ValueMeansContribution
trainedAlgorithmicMediaMade by a trained modelAI: strong evidence
compositeWithTrainedAlgorithmicMediaA composite that includes AI contentAI: strong evidence
algorithmicMediaRendered by an algorithm, such as procedural art or CGINot AI
compositeSyntheticA composite with synthetic contentDescribe only; do not claim AI

A file whose only evidence is algorithmicMedia is not reported as AI generated, because that value describes an algorithm rendering content and says nothing about a trained model. An unrecognised value is kept exactly as written and reported as inconclusive rather than guessed at.

Metadata, and its blind spot

Cameras, editors and generators leave text in EXIF, XMP and IPTC blocks. Trace parses those blocks and reports the raw values it finds, along with any generator marker it recognises: the Stable Diffusion parameters key, the ComfyUI prompt and workflow keys, software tags naming Google, Gemini, Imagen, DALL-E or Firefly, the XMP CreatorTool, and the IPTC DigitalSourceType.

Trace reports a match. It does not score it. Metadata is easy to strip and easy to forge, so a match is never proof and a lack of matches is never reassurance.

Google's Gemini API embeds its pixel watermark but writes no C2PA and no IPTC at all, so metadata checks read clean on those files. Any screenshot or social re-upload strips metadata entirely. A clean metadata read means the file carries no marker Trace recognises, and nothing more.

Why no watermark does not mean the media is real

This is the most widely misunderstood point in the whole subject, so Trace states it plainly.

  • Many generators embed nothing. Only some tools add a watermark at all. Open and self-hosted models such as Stable Diffusion, FLUX and Qwen, and most local pipelines, embed nothing, so there is nothing for any check to find.
  • Ordinary handling destroys provenance metadata. A screenshot, a social re-upload, a messaging app and any re-encode strip C2PA and EXIF. While cropping and compression do not necessarily remove a pixel watermark, they do remove the metadata that might have named the tool.
  • An abstention is not a clean result. When the service abstains it did not decide. Each abstention reason above is a reason a reading could not be made, not a statement that the content is genuine.
  • If the SynthID check is not configured, nothing ran. A blank watermark result means the check did not execute, because no key was available. It never means the file passed.
  • Watermark removal tools exist and are widely used. A stripped watermark looks identical to one that was never there. The absence of a watermark carries no information about how the media was made.

How to get a clearer reading

The mechanisms above point to practical steps.

  1. Upload the original. A screenshot repaints the pixels and removes metadata, which erases or distorts exactly what the checks look for.
  2. Do not downscale. Low resolution is one of the reasons the SynthID service abstains, and an abstention is the absence of a verdict.
  3. Stay within the size limits. An image must be under 8 MB, and audio or video under 100 MB. If a file is larger, crop it rather than let the check fail.
  4. Remove anything that is not the content. Screen chrome, social overlays, captions, letterbox bars, meme text, borders and other apps' watermarks dilute the signal. Crop to the content, not into it, and keep the whole generated frame.
  5. For video, crop the bars and trim to the AI segment. The service reports the share of frames that carry a watermark, so a clip that is part AI and part live action gives a mixed reading.
  6. Keep enough frames and avoid re-encoding more than once. Too few frames triggers the low frame rate abstention, and each re-encode can degrade the very watermark you are trying to check.

What Trace never does

Trace does not describe a file as authentic, safe, verified real, human made or not AI. There is no green all clear state, because an absent watermark is not a pass. It shows no percentage, probability or score that an authoritative source did not return, and it does not fold a check that never ran into a clean result.

Trace is a static site. There is no backend, no build step and no tracking.
