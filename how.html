Method and limits

How Trace works, and what each signal can and cannot tell you.

Trace reports signals. A signal is not a verdict about whether a picture is true, and the absence of a signal is never a clean bill of health. This page explains what each check measures, where it fails, and how to get a clearer reading.

The order of evidence

Not all signals are equal. A signed content credential from a known producer is vendor-authoritative evidence that a manifest exists and names its producer. A statistical probe over pixels is a heuristic, and heuristics produce false positives on ordinary photographs.

Trace sorts what it finds into a small set of verdicts. The verdict is a summary of the evidence present in the file you supplied. It is not a statement that the media is authentic, and it is not a statement that the media is false.

Absence of provenance is the normal case, not a suspicious one. Most images in circulation were never signed, and most re-encodes strip whatever was there.

C2PA and Content Credentials

C2PA is a standard for embedding a signed manifest inside a media file. The manifest can name the tool that produced the file, the signer, and, in the IPTC digitalSourceType field, the kind of process that made the content. Trace reads the manifest directly from the bytes. It locates the manifest store in JPEG, PNG, WebP and MP4 containers, expands the JUMBF boxes, and decodes the CBOR payload with a decoder written for this tool.

Trace can read the manifest and report its contents. It cannot verify the cryptographic signature, because that needs a full COSE and X.509 stack that pure browser JavaScript does not provide here. When a manifest is present and parses, the report says so and says plainly that the signature was not verified in the browser. Treat an unverified manifest as a claim, not a proof.

The digitalSourceType trap

This field is the most misread part of the whole subject. Four of its values look similar and mean very different things:

The digitalSourceType values and what each contributes
ValueMeansWeight
trainedAlgorithmicMediaMade by a trained modelStrong AI evidence
compositeWithTrainedAlgorithmicMediaA composite that includes AI contentStrong AI evidence
algorithmicMediaRendered by an algorithm, such as procedural art, CGI or a gradientNot AI
compositeSyntheticA composite with synthetic contentWeak; describe only

A file whose only evidence is algorithmicMedia is not reported as AI generated, because that value means an algorithm rendered it and says nothing about a trained model. Any unknown value is stored exactly as written and reported as inconclusive rather than guessed at.

Metadata and generator fingerprints

Cameras, editors and generators leave text in EXIF, XMP and IPTC blocks. Trace parses those blocks directly from the bytes and matches known fingerprints, including the Stable Diffusion parameters key, ComfyUI prompt and workflow keys, software tags naming Google, Gemini, Imagen, DALL-E, Firefly and Midjourney, the XMP CreatorTool field, and the IPTC DigitalSourceType field.

The blind spot is large. Google's Gemini API writes a pixel watermark and writes no C2PA and no IPTC at all, so metadata checks read clean on those files. Screenshots and social re-uploads remove metadata entirely. A clean metadata read means the file carries no fingerprint Trace recognises. It does not mean the file is human made.

Invisible watermark structure

Some generators perturb the frequency content of an image to carry a watermark. Trace computes a Haar wavelet decomposition and an 8 by 8 block DCT over the luminance channel, then measures the coefficient-difference statistics those schemes disturb, and reports a score with an interpretation band.

This is a statistical probe, not a decode. Trace never claims to have read a watermark, because it cannot. The score can rise on any image with strong periodic structure. Strong compression, resizing and cropping all flatten the signal, so a low score proves nothing.

Forensic signals

Trace runs three independent heuristics. Error level analysis re-encodes the image through a canvas at a known quality and measures the per-region difference. A spectral grid search runs a radix-2 FFT and looks for the periodic peaks that some generator decoders leave behind. A noise residual estimate measures high-frequency sensor noise.

All three are heuristics, and false positives are common on screenshots, re-encoded images and heavily processed genuine photographs. The absence of sensor noise is weak evidence, because denoising and re-encoding remove it too. Treat each as a prompt to look closer, never as a conclusion.

Visible marks

Trace performs a best-effort scan of the corners and the lower-right region for the on-image badges placed by Gemini, Sora, Veo, Kling, Seedance, Doubao and Hailuo. These badges are easy to crop and easy to counterfeit, so their presence is a hint and their absence carries no weight. When the scan cannot run, it reports that it was skipped rather than guessing.

The SynthID check

SynthID is Google's watermark for AI generated images, audio and video. Google runs an official verification API at synthid.googleapis.com, and Trace implements the call. The honest limitation is access: the API is restricted to Google Cloud accounts with SynthID access, granted through Gemini Enterprise and partner programmes, and it cannot be enabled from the public API library. An ordinary project key is rejected.

Because of that, when no key is set, or when the service blocks the request, Trace reports the check as not configured and links you to synthid.com, Google's free public SynthID Detector, which runs the same authoritative check for images, audio and video. The same check is also available inside the Gemini app. A blank SynthID result means the check did not run. It never means clean.

How to get a clearer reading

The mechanisms above suggest practical steps.

  • Upload the original file rather than a screenshot. A screenshot destroys metadata and repaints the pixels, which erases or distorts a pixel watermark.
  • Do not downscale. Low resolution triggers an abstention from the SynthID service, which is the absence of a verdict, not a clean result.
  • Stay within the size limits. The SynthID service accepts images up to 8 MB and audio and video up to 100 MB. If a file is larger, crop rather than let the check fail.
  • Crop to the content, not into it. Remove screen chrome, social overlays, captions, letterbox bars, meme text, borders and other apps' watermarks, because they are not part of the generated frame and they dilute the signal. Keep the whole generated frame.
  • For video, crop the bars, then trim to the segment that is actually AI generated. The service reports the share of frames that carry a watermark, so a clip that is part AI and part live action gives a mixed reading.
  • Keep enough frames to avoid the low frame rate abstention, and avoid re-encoding more than once. A re-encode can degrade exactly the watermark you are trying to check.

What Trace never does

Trace does not describe a file as authentic, safe, verified real, human made, or not AI. There is no green all-clear state, because an absent watermark is not a pass. No accuracy percentage is shown for any heuristic, because none was measured.

Trace is a static site. There is no backend, no build step and no tracking.
