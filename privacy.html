Privacy Policy

Your file stays in your browser, with one exception you control.

Trace is a static site. It has no backend, no database and no analytics. This page states exactly when, and whether, a file leaves your machine.

The short version

With no SynthID key configured, nothing you open, paste or drop leaves your browser. Not the file, not its bytes, not a summary of it. Every check runs in the tab.

With a SynthID key configured, the file is sent from your browser straight to Google at synthid.googleapis.com so the watermark can be read. That is the only outbound request Trace makes, and it happens only because you set a key.

What Trace does with your file

When you drop, paste or pick a file, the browser reads it into memory and every check runs in this tab. Trace parses the bytes locally, uses canvas and video elements locally, and renders the result locally. None of that touches the network.

Trace does not store your file. It does not write it to disk, it does not keep a copy after you navigate away, and it does not send a hash, a thumbnail or a size anywhere.

The one exception: the SynthID check

Google's SynthID verification API is the only outbound network request in the codebase, and it is called only when you configure a key. The behaviour is:

  • No key set. Trace does not call the API at all. The panel reports the check as not_configured and explains that a blank result means the check did not run, never that the file is clean. Nothing leaves your browser.
  • Key set. Trace sends the raw file bytes as the request body to https://synthid.googleapis.com/upload/v1:verifyContent, with the key in the query string and the media content type in the header. Google's response is shown to you. Google's handling of that request is governed by Google's own terms and privacy policy, not by this one.

The key you paste is held in your browser's local storage so it survives a reload. It is sent only to Google, as the API requires. Trace has no server that could receive it.

If you self-host Trace

The optional selfhost/ server serves the same static files and can hold the SynthID key on the server instead of in the browser. When it advertises that option, the check is sent to that server's /api/synthid endpoint, which forwards the body to Google with the server-side key. The file still does not need to be stored: the server forwards the bytes and discards them, and it never logs file contents, request bodies or the key. If you use this option, the server's operator can in principle observe the request, so only self-host with a server you trust.

Local storage

Trace uses your browser's local storage for one thing: to remember the SynthID API key if you choose to enter one. Nothing else is stored. You can clear it with the Clear key button in the settings panel, or by clearing site data in your browser.

No tracking, no third parties

There are no analytics, no advertising, no tracking cookies, and no third-party scripts. Fonts are served from this repository rather than a font CDN, and the C2PA library is vendored into this repository, so loading a page makes no request to any third party. The external links on this site open only when you click them.

Changes

If the behaviour of this tool changes in a way that affects what leaves your browser, this page will state the new behaviour plainly. The current statement is simple: nothing leaves the browser unless you configure a SynthID key.
